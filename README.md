# ربات مدیریت فوتسال

یک ربات تلگرام برای مدیریت افراد شرکت‌کننده در سانس‌های سالن فوتسال، نوشته شده با Go و PostgreSQL.

## ویژگی‌ها

- 🎯 مدیریت چند کلاس/گروه به صورت مستقل
- 👥 چهار نقش کاربری: Admin، Student، Adult، Half Adult
- 💰 تعیین نرخ مالی متفاوت برای هر نقش
- 📊 پیگیری جلسات بدهکار و صورتحساب
- ✅ سیستم تسویه حساب توسط ادمین
- 📈 گزارش‌گیری از بدهی‌های هر گروه

## پیش‌نیازها

- Docker و Docker Compose
- یک ربات روی بله یا تلگرام (برای تلگرام از [@BotFather](https://t.me/botfather))
- User ID عددی خودتان در همان پیام‌رسان

## انتخاب پیام‌رسان

ربات هم روی **بله** و هم روی **تلگرام** کار می‌کند. هر دو از همان Bot API استفاده
می‌کنند و فقط آدرس سرور فرق دارد. این با متغیر `PLATFORM` در فایل `.env` انتخاب می‌شود:

| PLATFORM | سرور |
| --- | --- |
| `bale` (پیش‌فرض) | `https://tapi.bale.ai` |
| `telegram` | `https://api.telegram.org` |

اگر مقدار دیگری بگذارید، ربات با خطای واضح بالا نمی‌آید.

⚠️ توکن و `DEFAULT_ADMIN_ID` باید از همان پیام‌رسانی باشد که در `PLATFORM` انتخاب
کرده‌اید. آیدی‌های بله و تلگرام یکی نیستند، و دیتابیس هم آنها را از هم جدا نمی‌کند —
پس برای هر پیام‌رسان از یک دیتابیس جدا استفاده کنید.

## نصب و راه‌اندازی

### 1. کلون کردن پروژه

```bash
git clone <repository-url>
cd futsal-bot
```

### 2. تنظیم فایل محیطی

فایل `.env.example` را کپی کنید به `.env`:

```bash
cp .env.example .env
```

سپس فایل `.env` را ویرایش کنید و مقادیر زیر را وارد کنید:

```env
# اطلاعات ربات
# PLATFORM مشخص می‌کند ربات روی کدام پیام‌رسان اجرا شود: bale یا telegram
# توکن و آیدی ادمین باید از همان پیام‌رسان باشد.
PLATFORM=bale
BOT_TOKEN=your_bot_token_from_botfather
DEFAULT_ADMIN_ID=your_user_id

# تنظیمات دیتابیس
DB_HOST=postgres
DB_PORT=5432
DB_USER=futsalbot
DB_PASSWORD=your_secure_password
DB_NAME=futsalbot
DB_SSLMODE=disable

# تنظیمات برنامه
APP_PORT=8080

# تنظیمات PostgreSQL (برای Docker)
POSTGRES_USER=futsalbot
POSTGRES_PASSWORD=your_secure_password
POSTGRES_DB=futsalbot
```

### 3. اجرای پروژه

```bash
docker-compose up -d
```

برای مشاهده لاگ‌ها:

```bash
docker-compose logs -f bot
```

برای متوقف کردن:

```bash
docker-compose down
```

برای حذف کامل (شامل دیتابیس):

```bash
docker-compose down -v
```

## استفاده

### دستورات پرایوت (PV)

- `/start` - شروع کار با ربات و نمایش منوی اصلی

### دکمه‌های پرایوت

#### برای همه کاربران:
- **ثبت نام** - ثبت نام در یک کلاس
- **ویرایش مشخصات** - ویرایش نام و نقش
- **صورتحساب** - مشاهده تعداد جلسات بدهی و مبلغ کل

#### برای ادمین‌ها:
- **تعیین نرخ** - تعیین نرخ مالی برای هر نقش
- **تسویه حساب کاربر** - تسویه حساب دستی کاربران
- **ایجاد سانس** - ساخت یک سانس جدید (ماه، تاریخ، ظرفیت). ربات تابلوی حاضرین و
  غایبین را در گروه می‌فرستد و برای همه اعضای ثبت‌نام‌شده دکمه اعلام حضور ارسال می‌کند.
- **بستن سانس** - بعد از آن دیگر کسی نمی‌تواند پاسخش را تغییر دهد
- **ارسال صورتحساب به همه** - ارسال صورتحساب هر عضو در پیوی خودش

### اعلام حضور در سانس

هر عضو در پیوی ربات دو دکمه می‌بیند:

- **✅ میام** - دقیقاً مثل ثبت حضور با `/attendance` است و یک جلسه به حساب او اضافه می‌شود
- **❌ نمیام** - جلسه‌ای اضافه نمی‌شود

تا وقتی ادمین سانس را نبسته، عضو می‌تواند پاسخش را عوض کند و حساب او خودکار اصلاح
می‌شود. بعد از هر پاسخ، صورتحساب آن سانس برای خودش ارسال می‌شود.

### دستورات گروه

⚠️ **توجه:** این دستورات فقط توسط ادمین‌ها قابل اجرا هستند.

- `/attendance [user_ids...]` - ثبت حضور و غیاب

  کاربران فقط با آیدی عددی (که یکتا است) مشخص می‌شوند، نه با `@username`.
  ```
  مثال: /attendance 123456789 987654321
  ```

- `/report` - نمایش گزارش بدهی‌های گروه

## جداول دیتابیس

### users
ذخیره اطلاعات پایه کاربران تلگرام

### groups
ذخیره اطلاعات گروه‌ها/کلاس‌ها

### user_groups
ذخیره عضویت کاربران در گروه‌ها با نقش و بدهی آنها

### rates
ذخیره نرخ مالی هر نقش در هر گروه

### events
ذخیره سانس‌ها (ماه، تاریخ، ظرفیت و آیدی پیام تابلو در گروه)

### event_responses
ذخیره پاسخ حاضر/غایب هر کاربر برای هر سانس

> ⚠️ شماره مایگریشن `005` قبلاً برای جدول `attendance_records` استفاده شده و حذف
> شده است. آن شماره سوخته است و هرگز نباید دوباره استفاده شود، چون goose آن را
> در جدول `goose_db_version` به عنوان اجراشده ثبت کرده است.

## توسعه

### ساخت مجدد تصاویر Docker

```bash
docker-compose build
```

### اجرای مایگریشن‌ها به صورت دستی

مایگریشن‌ها به صورت خودکار هنگام شروع برنامه اجرا می‌شوند.

### دسترسی به دیتابیس

```bash
docker-compose exec postgres psql -U futsalbot -d futsalbot
```

## عیب‌یابی

### مشاهده لاگ‌های ربات

```bash
docker-compose logs bot
```

### مشاهده لاگ‌های PostgreSQL

```bash
docker-compose logs postgres
```

### بررسی وضعیت سرویس‌ها

```bash
docker-compose ps
```

### راه‌اندازی مجدد سرویس‌ها

```bash
docker-compose restart
```

## امنیت

- ⚠️ حتماً `DB_PASSWORD` را در فایل `.env` تغییر دهید
- فایل `.env` را به Git اضافه نکنید
- از HTTPS برای ارتباط با Telegram API استفاده می‌شود
- پورت‌های اکسپوز شده فقط روی localhost قابل دسترسی هستند
